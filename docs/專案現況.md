## 3. 🟠 已知缺陷：取消 DH 後，P 沒有自動進入 DH 的打序位置

**使用者 2026-09-26 回報，尚未實作。**

### 需求（使用者原話）

> 取消 DH 後，P 進入打線取代 DH 的打序位置。

也就是說，DH 制中途取消時，投手應該接替**原本 DH 的棒次**，進入打線。
目前工具**沒有這個功能**：DH 取消後，投手只會出現在更換視窗的候選名單裡（見 V01.02.02 的 `subCandidates` 修正），要由記錄員自己挑一個棒次放進去，工具不會自動把 P 放進 DH 的棒次。

### ⚠️ 與現行規則依據的差異（動工前必須先跟使用者確認）

現有的 DH 邏輯與測試是依照 **MLB Rule 5.11(a)(5)** 寫的：

> DH 上場守備時，DH 的棒次不變，但**投手必須接替「被換下的守備球員」的棒次**。

使用者的需求是「P 取代 **DH** 的打序位置」。兩者在部分情境下會產生**不同的打線**：

| 情境 | 5.11(a)(5)（現行測試的依據） | 使用者的需求 |
|---|---|---|
| DH 上場守備（例：DH 去守 RF，原 RF 下場） | DH 留在原棒次改守 RF，**P 進原 RF 的棒次** | P 進 DH 的棒次？（DH 本人還在場上，需釐清） |
| DH 被換下場、未上場守備 | — | P 直接接替 DH 的棒次 |
| 投手轉守其他守位（Rule (8)） | 新投手接替另一棒 | 需釐清 |
| 代打者之後上場投球（Rule (9)） | 該球員已在打序中 | 需釐清 |

**接手者動工前，請先跟使用者逐一確認**：
1. 這條規則適用在哪些 DH 取消的途徑？全部？還是只適用「DH 退場、沒有上場守備」的情況？
2. 若 DH 本人去守備、仍在打線上，P 要進哪一棒？
3. 自動放入後，記錄員能不能手動改到別的棒次？
4. 聯盟（大漢聯盟）的規則是否與 MLB 不同？如果是，以聯盟規則為準。

### ⚠️ 開發時必須測試

這個改動會碰到 `lineup.html` 的 DH 取消判定與調度邏輯，**一定會影響既有測試**：
- **C1、C7、G3**（見 `測試報告_調度三情境.md`）是照 5.11(a)(5) 寫的，規則定案後要**重寫期望值**，不能為了讓測試變綠就直接改斷言
- 為使用者確認過的每一條 DH 取消途徑，**各新增一個測試案例**，終點斷言維持「九個守位齊全、沒有重複、投手在打序中」
- 做一次**變異測試**：把新邏輯拿掉，新案例必須轉紅
- 三支測試全部重跑，加上 `--repeat 5`（指令見第 5.3 節）
- 部署後在正式試算表跑一場驗證分頁，回讀確認，**驗證完記得提醒使用者手動刪除該分頁**

### 6.1 三頁

### 6.2 球隊活動慣例

- 活動固定在**週日**。有比賽就不練球，沒比賽就練球 08:00～12:00
- 練球 `08:00` 是**開始時間**，不是集合時間
- 比賽**一律開賽前一小時集合**，但 `gatherTime` 仍存進 JSON，保留例外的彈性
- 大漢聯盟賽程**約兩個月前才公布**，所以先把沒比賽的週日全排成練球，賽程公布後再改成 `game`

### 6.3 首頁大版位的行為

- 顯示第一個「日期 >= 今天且未取消」的活動，比賽和練球都可能佔據這個位置
- 落在本週（到本週日為止）時標題寫「本週活動」，已跨到下週時寫「下次活動」
- 比賽用深黑底＋紅邊＋大字；練球用白底＋金邊
- 旁邊固定一張「下一場比賽」小卡；如果大版位已經是那場比賽，就不重複顯示
- 活動當天顯示到午夜，隔天自動換成下一個

## 7. 資料格式（完整規格）

### 7.1 `data/announcements.json`

陣列，新的在前：

```json
[
  {
    "date": "2026-09-23",
    "title": "秋季聯賽開打",
    "body": "第一場 10/25 對 ZERO。\n集合時間 9:00。",
    "pinned": false
  }
]
```

- `body` 用 `\n` 換行，前端會渲染成段落
- `pinned: true` 會排在最前面
- **不做分類、不做標籤**

### 7.2 `data/schedule.json`

陣列，依 `date` 排序：

```json
[
  {
    "type": "game",
    "date": "2026-10-25",
    "gatherTime": "09:00",
    "startTime": "10:00",
    "venue": "大漢B球場",
    "opponent": "ZERO",
    "score": null,
    "resultUrl": null,
    "cancelled": false,
    "note": ""
  },
  {
    "type": "practice",
    "date": "2026-11-08",
    "startTime": "08:00",
    "endTime": "12:00",
    "venue": "",
    "cancelled": false,
    "note": ""
  }
]
```

規則：
- `type` 只能是 `game` 或 `practice`
- **不存星期和 `status`**，由前端從 `date` 計算，避免資料自相矛盾
- `cancelled`：取消是外部事實，無法從日期推導，所以要存。時程頁會顯示灰底刪除線＋紅色「已取消」，首頁大版位會自動跳過
- **改期** = 原本那筆標成 `cancelled: true`，另外新增一筆新日期，再發一則公告說明
- `venue` 留空 → 前端顯示「地點未定，請留意公告」
- `score` 比完手動填 `{ "longan": 7, "opponent": 3 }`，時程頁會自動判斷勝／敗／和並上色
- **`resultUrl` 一律 `null`**，前端不會渲染成連結。這是預留給階段 E 賽事成績頁的接口

### 7.3 內容維護方式

三條路並存：口述給 Claude、在 GitHub 網頁直接編輯、使用 `/tools/` 的兩個產生器（**推薦**）。
產生器的用法是「填好 → 產生整份檔案內容 → 複製 → 貼到 GitHub 編輯框（全選刪掉舊的再貼上）→ Commit」。
**產生器不會寫入任何資料**，所以不需要登入，也沒有金鑰外洩的風險。這是刻意的設計。

## 10. 📘 文字記錄簡碼字典（定為後續執行）

**狀態**：v1 草案，使用者 2026-09-14 起草，**尚未實作，排在 10/25 首戰之後**。原文見同資料夾的 `文字記錄簡碼字典.md`。

### 10.1 目的

記錄員在場邊用文字記錄整場比賽的經過，之後由**規則式解析器**依照簡碼，把文字轉換成結構化成績（AB／H／R／RBI／BB／K…），自動寫進試算表。

- **不使用 AI 模型解析**，純粹用字串比對／正規表示式處理。原因是格式已經結構化、不需要理解語意，規則式更精準、免費，也不需要外部 API
- 原本規劃取代舊的 `stats.html`（球員各自上傳成績）；`stats.html` 已於 09-20 移除，所以**目前成績只能手動輸入**，這個功能就是要補上這個缺口
- 解析器要放在前端（改建後的成績工具）還是 GAS 端，**尚未決定**

### 10.2 記錄格式總規則

每一行 = **自然語言描述**（給人看，寫法自由，方便事後複盤，程式不解析）＋ **結構化事件清單**（給程式解析，格式固定）＋（可選）即時比分。

```
[棒次/情境]　自然語言描述這一球發生了什麼事。
　→ 姓名1:簡碼1[,打點N]／姓名2:簡碼2／姓名3:簡碼3…　(比分 X:Y)
```

- 一個「姓名:簡碼」為一組，多組用「／」分隔。**一行可以同時記錄打者本人和任意數量的跑者事件**
- **打點**是可選的附加寫法，格式為「簡碼,打點N」，只能接在**打者自己那組**後面。沒寫就是 0。發生守備失誤時是否認列打點，由記錄員主觀判斷
- 姓名一律使用球員名單上登記的姓名（或暱稱），系統會比對球員名單。**比對不到的名字會列進「⚠️ 無法辨識」清單交給人工確認，不能默默忽略**
- **不追蹤壘包狀態**：系統不會推算「誰現在在幾壘」。每一行都必須具名說清楚「誰、發生了什麼事」，不能寫「2 壘跑者」這種不具名的寫法

### 10.3 簡碼一覽

**① 安打（算 AB，算 H）**

| 簡碼 | 說明 |
|---|---|
| 一安 | 一壘安打 |
| 二安 | 二壘安打（2B+1） |
| 三安 | 三壘安打（3B+1） |
| 全打 | 全壘打（HR+1；打者自動算得分，不需另外寫「得分」） |

**② 保送與觸身（不算 AB）**

| 簡碼 | 說明 |
|---|---|
| 四壞 | 四壞球保送（BB+1） |
| 觸身 | 觸身球（HBP+1；嫌麻煩可以直接寫「四壞」代替） |

**③ 出局（依守位，算 AB，不算 H）**

| 簡碼 | 說明 |
|---|---|
| 投滾／捕滾／一滾／二滾／三滾／游滾 | 該守位處理的滾地球出局 |
| 投飛／捕飛／一飛／二飛／三飛／游飛／左飛／中飛／右飛 | 該守位處理的高飛球或平飛球出局 |

**④ 三振（算 AB，不算 H，K+1）**

| 簡碼 | 說明 |
|---|---|
| 三振(揮) | 揮棒落空 |
| 三振(看) | 看第三顆好球 |

兩者對成績的影響相同，差別只在紀錄細節。

**⑤ 特殊上壘或出局**

| 簡碼 | AB | H | 說明 |
|---|---|---|---|
| 犧飛 | 不算 | 不算 | 高飛犧牲打 |
| 犧觸 | 不算 | 不算 | 犧牲觸擊 |
| 野選 | 算 | 不算 | 野手選擇（防守方處理別的跑者，沒有失誤） |
| 失誤上壘 | 算 | 不算 | 因守備失誤上壘；造成失分時是否算打點由記錄員判斷 |

**⑥ 跑者事件（接在該跑者自己的名字後面）**

| 簡碼 | 說明 |
|---|---|
| 得分 | 跑回本壘（R+1） |
| 封殺出局 | 跑壘中被封殺 |
| 觸殺出局 | 跑壘中被觸殺 |
| 盜壘成功 | SB+1 |
| 盜壘失敗 | CS+1（可選欄位） |

**⑦ 投手端固定句型（半局結束或換投時獨立一行，不是「姓名:簡碼」格式）**

| 寫法 | 說明 |
|---|---|
| 本局失分:N | 累加到當局投手的 R |
| 責失分:N | 累加到當局投手的 ER（不確定就寫得跟失分一樣，事後可以人工調整） |
| 換投:XXX 接手 | 標記投手交接點，之後的失分算在新投手身上 |
| 暴投／捕逸 | 純紀錄用，目前不影響任何計算欄位 |

**⑧ 代打／代跑（草案，尚未用實際案例驗證）**

| 寫法 | 說明 |
|---|---|
| 代打:XXX 代替 YYY | YYY 被換下場，XXX 代打上場 |
| 代跑:XXX 代替 YYY | YYY 被換下場，XXX 代跑上場 |

### 10.4 已用實際案例驗證過的範例

**一般安打**
```
1. 蘇垣華　三壘方向滾地球，內野安打。
　→ 蘇垣華:一安　(1:0)
```

**一次多分打點（二、三壘有人，打者二壘安打，兩名跑者回本壘）**
```

```

**封殺＋守備失誤＋得分同時發生（一出局，一、三壘有人）**
```
3. 陳奕瑋　擊出游擊方向滾地球。游擊手傳二壘，一壘跑者林廷軒遭封殺出局；二壘手轉傳一壘時發生守備失誤，陳奕瑋因此安全上壘；三壘跑者李浩瑋趁亂回本壘得分。
　→ 陳奕瑋:失誤上壘／林廷軒:封殺出局／李浩瑋:得分　(2:1)
```
