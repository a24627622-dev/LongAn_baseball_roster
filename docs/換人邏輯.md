> V01.16.00 把陣容調度第三步「調度（備援）」的**畫面**拿掉（比賽中換人改在實況賽事紀錄記），

## 1. 為什麼留著

- 這套邏輯對標 MLB 規則（DH 5.11(a)、多重換人、投手轉守），是 2026-09 花最多時間驗證的部分（`docs/測試報告_調度三情境.md`）
- 之後「兩個工具合併成一頁」（專案現況第 10 節）時，實況賽事紀錄的換人要用同一套規則
- 實況賽事紀錄的換人目前在 `game-core.js`（調度紀錄換人／換位置、承繼跑者）。兩邊的 DH 規則是否完全一致**還沒逐條比對**；合併時以這裡的規則與 26 項情境為準

## 2. 規則與程式位置（`tools/lineup.html` 的 `setup()`）

| 規則 | 函式／計算值 | 說明 |
|---|---|---|
| 換人視窗 | `openSubModal(battingOrder)`、`confirmSubstitution()` | 代打（PH）、代跑（PR）、換守位（同一人改守位）、新球員上場；同一批未上傳的換人可刪（`removeSubstitute`） |
| 候選名單 | `subCandidates`、`benchPlayers` | 板凳＝點名有到、沒上過場的人；DH 制時目前的投手也選得到（可以進打序） |
| DH 取消判定 | `willCancelDH`、`isDHCancelled`、`isDHSlot()` | MLB 5.11(a)：投手進打序、DH 去守備、代打 DH 後改守備等，DH 就取消；代打 DH 後接著當 DH 不算取消 |
| DH 引導 | `openDHFollowUp()` | DH 去守備 → 自動帶出「投手打被換下那一棒」；投手轉守其他位置 → 帶出 DH 那一棒的換投（V01.02.03） |
| 不合法投手棒次 | `illegalPitcherSlot`、`pitcherNotBattingAfterDH` | DH 有效時投手只能打 DH 那一棒；DH 取消後投手沒進打序 → 紅字提示 |
| 換投（DH 制） | `confirmIndependentPitcherChange()`、`removeIndependentPitcher()`、`extraPitchersHistory` | 投手不在打序時的換投 |
| 場上投手名單 | `activePitchers` | 先發＋後援投手，依上場順序，不重複（試算表投手表用） |
| 守備完整檢查 | `activeDefenseNotice` | 守位不重複（重複時擋上傳）；「尚缺守位」不擋（代打／代跑後的合法中間狀態） |
| 上傳與解鎖 | `uploadSubstitutionsToGAS()`、`unlockLastBatch()` | 一批一批上傳；解鎖只抽回最新一批 |
| 比賽結案 | `finishGame()` | 同步最終名單、蓋結束時間、清草稿（現在由實況賽事紀錄的「比賽完成」取代） |
| LINE 打單 | `currentLeagueReportText`、`copyLineup()` | 換人後的打單文字 |

GAS 端對應：`gas/Code.gs` 的 `saveSubstitutions`／`saveChanges`／`finishGame`（寫打者表替補列、投手表）、`gas/Pitchers.gs`。

## 3. 守著它的測試（每次 commit 前都跑）

| 測試 | 內容 |
|---|---|
| `tests/test_scenarios.js`（26 項） | 三大調度情境（A 一般 9 人、B 全場 DH、C DH 中途取消）、規則守門（G）、DH 引導（D）；每個案例都檢查不變條件：守位不重複、成績合計剛好 2 列、打者表不重複、投手不重複、先發投手剛好 1 位（**不能拿掉或放寬**） |
| `tests/test_lineup_logic.js` | A1～A3、B1～B5、C1～C3、D1～D4、F1～F8、G7（V01.16.00 起直接呼叫換人函式）等換人與回讀相關項目 |

測試框架：`tests/harness.js` 把 `lineup.html` 的 `<script>` 抽出來執行 `setup()`，不需要畫面，所以畫面拿掉不影響。
