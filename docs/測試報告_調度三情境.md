## 三、測試方法

完整鏈路重現，不是模擬點擊：

```
lineup.html 的 <script>          ← 直接從檔案抽出，不是複製品
        ↓ Node VM ＋ 極簡 Vue 替身執行 setup()
前端狀態（點名 → 先發 → 調度）
        ↓ 真實 payload
gas/Code.gs + Auth.gs + Pitchers.gs   ← 真實後端程式碼
        ↓ doPost
MockSpreadsheet（模擬試算表）
```

### 每案都跑的共同健全性檢查

1. **守位重複必須為空** —— 守位重複在比賽的任何瞬間都不可能成立
2. 「成績合計」剛好 2 列（打者表 1、投手表 1）
3. 打者表的合計列緊接在最後一筆資料列下方（防 V01.00.02 那類位移事故）
4. 打者表無重複列
5. 投手表無同一位投手重複、先發投手恰好 1 位

**「尚缺守位」不納入強制檢查** —— 代打／代跑之後守備還沒輪到，那是合法的中間狀態。
工具的 `conflicts` / `missing` 本來就分開，這個區分是對的。

## 五、過程中查出並修正的三個問題

### 問題一：DH 因「去守備」而取消後，投手在 UI 上永遠選不到

`subCandidates` 原本的條件是 `hasDHInLineup && !isDHCancelled && activePitchers.length > 0`。
但「DH 去守備」**本身就會讓 `isDHCancelled` 變 true**，於是 Rule (5) 要求的下一步
「投手接替被換下者的棒次」在 UI 上做不到 —— 現任投手既不在板凳名單，也不再被加回候選。
打線卡在缺投手的非法狀態，無解。

**修法**：改成只要該投手**尚未進入打序**就保留在候選名單，與 `isDHCancelled` 無關。

**為什麼一直沒被發現**：既有的 28 項裡本來就有一案寫的正是正確序列，
但測試框架的 `sub()` 直接塞 player id、繞過了候選名單，所以它一直是綠的。

### 問題二：守位重複時仍可上傳

步驟三的上傳按鈕先前不受 `activeDefenseNotice` 約束（只顯示紅字）。
現在 `conflicts` 非空時 disable 按鈕，函式本身再擋一層並說明原因。`missing` 不擋。

### 問題三：成績保留的比對 key 會碰撞

`savedStats` 的 key 是「打順｜姓名｜角色」。
在「替補球員自己換守位」時兩列同 key（例如都是 `1|↳ 謝替|替補`），
讀取時後者覆蓋前者；加上「-」之後，重寫會把該球員真正的成績換成「-」而**永久消失**。

**修法**：key 再帶上「第幾次出現」。由 A6 守著。

## 六、打者表的「-」顯示慣例（使用者定案）

同一位球員在同一棒次換守位時會產生兩列。第二列是**守位變更紀錄**，不是另一筆打擊紀錄：

```
2  3B (5)   黃三      先發   AB 3  H 2  …   公式 公式 公式 公式   ← 打擊成績記這裡
2  P (1)    ↳ 黃三    替補   -  -  -  …     -    -    -    -      ← 守位變更
```

**通則**：每個「棒次＋球員」組合，第一列帶成績，之後同一人的列都填「-」。
投球成績本來就另外記在投手表，不會漏。真正的換人（不同球員）不受影響。

**實作細節**：率值欄寫字串而非公式 —— 若 AB 欄是文字「-」，
Sheets 的 `"-" > 0` 會判定為 TRUE，公式會算出無意義的值。
成績合計的 SUM 會自動忽略文字，總數不受影響。

## 九、一個被收回的結論

第二版曾回報「`willCancelDH` 與 `isDHCancelled` 判定不一致 —— 警告不跳但 DH 被取消」。

**這個結論不成立。** 該情境是測試框架繞過候選名單、選到一個**已退場**的球員才做出來的，
真實 UI 無法重現（`benchPlayers` 本來就排除所有出現過的人，`subCandidates` 只加回**現任**投手）。
`isCurrentDHPitcher` 的判定正確且足夠。

**教訓**：測試框架如果比真實 UI 寬鬆，不只會讓測試失去意義，還會製造出假的 bug 報告。
因此 `harness.js` 的 `sub()` 已加上候選名單驗證：選一個不在 `subCandidates` 裡的球員會直接丟出錯誤。

## 十、仍未涵蓋的範圍

誠實列出，避免把「68 項全綠」當成「沒問題」：

- **畫面本身**：不載入 Vue／Tailwind，版面與手機可用性仍需實機確認。
- **Google Sheets 實際格式化**：底色、粗體、欄寬未驗證。
- **多重換人的棒次指定介面**：Rule (5) 允許教練指定棒次，工具目前沒有引導，
  記錄員必須自己知道要選哪一棒（例如接替「被換下者」空出的那一棒）。
- **`stats.html`**：送的 `savePlayerStats` 在 `Code.gs` 沒有對應分支，顯示成功但不寫入。**待決定處置**。
- **重複背號**：球員名單有兩位 `#18`（江佑霖、李浩偉）。
  工具的 id 是「背號_姓名」所以不會混淆，但值得留意。
- **併發**：兩支手機同時上傳同一場比賽未測。
- **`AUTH_ENFORCED=true`**：單元測試涵蓋登入流程，但線上仍是測試模式，尚未在真實環境開啟過。
