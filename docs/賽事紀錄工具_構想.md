## 1. 目標

做一個互動式的賽事紀錄工具，以打序為順序、逐打席記錄最終結果。

要解決的問題：文字紀錄時，「現在誰在幾壘、幾出局」全靠記錄員記在腦中，分心一次，之後每一筆都可能出錯。互動工具把狀態一直顯示在畫面上，並主動擋掉明顯的錯誤。

---

## 2. 兩個工具的分工

| | 調度工具（`lineup.html`） | 紀錄工具（新） |
|---|---|---|
| 使用時機 | **賽前** | **賽中、賽後** |
| 工作 | 點名、選擇有沒有 DH、排先發 | 記打席、跑者、比分；賽中所有調度（代打、代跑、換投、守位調動）；上傳 |
| 交接 | 開賽時把**整份陣容狀態**交給紀錄工具 | 接手後就是唯一能改陣容的地方 |

- 賽中換人**只在紀錄工具做**，避免出現兩份名單。調度工具的「比賽調度」步驟只剩賽前用途。
- 交接的是整份陣容狀態，不只是先發名單：打序（棒次、球員、守位）、現任投手、DH 狀態（沒有／有效／已取消）、已退場名單。
- 交接方式：同一支手機用瀏覽器本地儲存；不同手機時，從試算表讀取該場先發（`getGameLineup` 約 2 秒，開賽前讀一次可接受）。

## 3. 打席記錄

### 3.1 基本原則

- **只記每個打席的最終結果**，不逐球記錄，也不記投球數。
- **以半局為單位**確認與修正：三出局後顯示「本局得 X 分」，對照計分板；修改時只重算該半局。

### 3.2 打者結果兩層分類

第一層只看一件事：**打者本人最後在壘上，還是出局**。

- **上壘**：一安、二安、三安、全壘打、四壞、觸身、失誤上壘、野選、不死三振上壘
- **出局**：三振、滾地、飛球、平飛、觸擊、其他（犧飛、犧觸、雙殺都在這裡，由工具判斷）

記錄員只判斷眼睛看到的事實；算不算打數、算不算安打，由工具在背後處理。

### 3.3 操作順序

1. 上壘／出局
2. 擊球類型（三振、四壞、觸身不用選守位，直接跳到第 4 步）
3. 守位（出局必選；安打的方向可以略過）
4. 跑者確認：工具先給預設去向，沒問題直接送出，有例外才點
5. 送出，換下一位打者

### 3.4 跑者：預設推進＋調整例外

- 追蹤壘包。每位跑者的位置由工具掌握。
- 預設：安打依壘數推進；四壞、觸身只推被擠的跑者；出局類不動（例外見規則漏洞清單 C1）。
- 例外：點該跑者改去向，並選原因（趁傳球、失誤、暴投；出局時選封殺、觸殺、回壘不及）。
- 雙殺不另設選項：同一球出現兩個出局就自動標雙殺。
- 第三出局是打者出局或封殺時，該球得分不算；觸殺要確認跑者是否先踩本壘。

### 3.5 打席中的跑壘事件

- 盜壘、暴投、捕逸、牽制等，用「跑壘事件」記錄，並標原因。
- 跑壘事件造成第三出局時，打者**下一局第一個打擊**，這次不算打席。工具的「下一位打者」停在原棒次。

## 4. 賽中調度

### 4.1 原則：先換人，再排守位

1. **先換人**（當下就做）：代打、代跑、換投發生時，只處理誰進、誰出、接哪一棒。守位可以先空著（合法的中間狀態，沿用現有工具的 `missing`）。
2. **再排守位**（換局前的檢查點）：一次排好九個守位。守位重複要擋下；缺位沒補齊不能開始守備（沿用現有工具的 `conflicts` / `missing` 區分）。

守備半局中途換人時，兩步要在同一個畫面連續完成：每個打席開始前，九個守位都必須齊全。

### 4.2 四個入口

| 入口 | 時機 | 進去後 |
|---|---|---|
| 打者卡的「代打」 | 進攻中 | 直接帶入這一棒的代打選單 |
| 點壘包上的跑者 | 進攻中 | 帶入代跑選單，壘包上的名字跟著換 |
| 頂部常駐「調度」按鈕 | 任何時候 | 打序畫面，可換人，也可直接排守位（板凳用完時也能調守位） |
| 三出局自動跳出 | 換到我方守備前 | 直接進入排守位；沒變動時一鍵確認 |

### 4.3 三種賽制情境

開賽時只有兩種設定：**有 DH** 或 **沒有 DH**。「DH 中途取消」是有 DH 的比賽在賽中發生的事件。

| | 一般（投手打擊） | 全場 DH | DH 中途取消 |
|---|---|---|---|
| 打序 | 投手在打序 | 投手不在打序，DH 占一棒 | 取消後投手接進某一棒 |
| 換投 | 新投手接原投手棒次 | 只換投手，打序不動 | 取消後照一般方式 |
| 代打、代跑 | 代打投手後，換局要補投手 | 替 DH 代打或代跑，新球員接任 DH，不取消 | 代打者之後投球會觸發取消 |
| 換局檢查 | 九守位含投手 | 九守位＋DH，投手另外記 | DH 那一列消失，投手要有棒次 |

兩個設計讓三種情境共用一套：

- **輪到誰打看棒次，不看人**：那一棒換成誰，就由誰打。
- **「現任投手」和打序分開存**：一般賽制兩者重疊，DH 制分開，DH 取消時從分開變成重疊。

### 4.4 DH 取消的連動

DH 取消的觸發動作多半發生在排守位時（Rule 5.11(a)(8)(9)(12)），會讓「換守位」反過來牽動「換人」。工具要先提示再連動，例如：

> DH 陳某改守右外野，DH 將取消。原右外野手退場，投手張某接第 6 棒。

確認後自動補上這筆換人，再回到守位檢查。多重換人時由教練指定棒次（Rule 5.11(a)(5)），要讓記錄員選擇。

## 5. 比賽時間軸

- 放在**紀錄工具**的打席輸入畫面下方。打席和調度記在**同一條**時間軸上。
- 顯示時**以半局收折**：進行中的半局展開，已結束的半局收成一行摘要（得分、安打、調度筆數、殘壘）。點開某個半局可以修改其中一筆，只重算該半局。
- 收折只是顯示方式，資料本身是一條完整的時間軸。
- 共用一條時間軸的用途：
  - **復原**：「復原上一筆」也能復原調度。只在進行中的半局有效；已確認的半局要改，走「點開修改」。
  - **成績歸屬**：每個打席發生時誰在打、誰在投，照先後順序確定。
  - **承繼跑者**：跑者上壘時記下責任投手，換投後他得分，失分算回前一位投手。

## 6. 資料與儲存

### 6.1 三層資料

```
① 手機本地        比賽進行中，每一筆操作立刻存
      ↓ 每半局結束＋比賽結束時上傳
② 事件分頁        原始時間軸，一筆打席或調度一列（真實來源）
      ↓ 產生器計算
③ 衍生資料        單場成績、戰報、整季統計、官網資料檔
```

- **存原始事件，成績全部由事件算出來**。要修正就改事件、重算。
- 比賽中不每打席呼叫 GAS，避開冷啟動等待。手機壞掉最多只遺失進行中的半局。

### 6.2 放在哪裡

| 試算表 | 內容 | 性質 |
|---|---|---|
| **現有這份**（GAS 已綁定） | 球員名單、調度紀錄、**比賽事件**（新分頁） | 原始資料 |
| **新開一份** | 單場成績彙整、整季統計 | 衍生資料，隨時可重算 |

- 事件分頁用「保護工作表」鎖起來，只有維護者能手動編輯；GAS 以維護者帳號執行，寫入不受影響。
- 不採用 NAS 或 Firebase 等外部資料庫：資料量很小（一場約一百列），現有 GAS＋隊務登入就能用。只有未來要做即時轉播或多機即時同步時才重新評估。

### 6.3 賽後流程

| 步驟 | 在哪裡 | 誰觸發 |
|---|---|---|
| 1. 比賽結束 | 紀錄工具 | 記錄員 |
| 2. 上傳事件 | 紀錄工具 → GAS → 事件分頁 | 記錄員 |
| 3. 統計單場成績 | 產生器 | 自動 |
| 4. 生成戰報 | 產生器（沿用文字轉播） | 自動 |
| 5. 確認無誤，併入統計試算表 | 統計試算表 | **維護者確認後才執行（把關點）** |
| 6. 上傳官網 | 匯出 JSON → commit 進 repo | 維護者 |
| 7. 官網顯示 | 讀 repo 靜態檔，直到下次更新 | 自動 |
| 8. 下一場重複 | | |

- 官網只讀不寫，而且沿用既有決定：**對外頁面讀 repo 的靜態 JSON，不直接呼叫 GAS**（冷啟動慢、無快取、配額算在個人帳號）。
- **每一層都以比賽代號覆蓋，不是累加**（代號沿用 `YYYY-MM-DD_Gx_對手`）。同一場重跑一次，整季統計結果要相同，才能支援「改事件 → 重算 → 重新併入 → 重新上傳」的賽後修正。
- 戰報發布後，把 `schedule.json` 該場的 `resultUrl` 指過去（這個欄位原本就保留給階段 E）。
