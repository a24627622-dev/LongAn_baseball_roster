## A. 死球／安全進壘

### A1. 觸身球只能擠壘【使用者測試】
- 問題：範例可以讓沒被擠的跑者多跑，也可以選出局。
- 規則：觸身球是死球。打者上一壘，只有被擠的跑者前進一個壘，其他跑者不能動。
- 修正方向：觸身球時跑者畫面鎖定，不提供選項，只顯示結果。
- 測試：
  - 一、三壘有人，觸身 → 一壘跑者上二壘，三壘跑者留在三壘，不得分。
  - 滿壘，觸身 → 三壘跑者擠回本壘得分，打者打點 1。

### A2. 四壞保送的預設與例外【使用者測試，需修正理解】
- 使用者的理解：四壞和觸身一樣是死球，跑者只能被擠。
- 一般規則：**四壞保送是活球**（故意四壞除外）。被擠的跑者安全進一個壘，但跑者可以自己冒險多跑。例如第四壞時一壘跑者同時盜壘，捕手傳歪，跑者上到三壘。
- 修正方向：
  - 預設只推進被擠的跑者。
  - 多跑的部分當作例外：必須選原因（盜壘、暴投、捕逸、失誤），也可以選出局。
  - 被擠的跑者不能選「留原壘」。
- 待查證：沒被擠的跑者在第四壞時進壘，計分上該記成什麼。
- 待查證：大漢聯盟是否採用故意四壞直接申告。若採用，故意四壞比照 A1 處理。
- 測試：
  - 二壘有人，四壞 → 預設二壘跑者不動（沒被擠）。
  - 一壘有人，四壞，一壘跑者多跑到三壘 → 必須選原因才能送出。

### A3. 缺少「妨礙打擊」選項【預先列出】
- 捕手妨礙打擊時，打者上一壘，不算打數。範例目前沒有這個選項。
- 待查證：跑者如何處理。

## B. 犧牲打與打點

### B1. 高飛犧牲打要明確呈現【使用者測試】
- 問題：0 出局、三壘有人高飛，把跑者改成得分後，畫面沒有明確顯示「犧飛」。
- 範例現況：送出後只有在打擊類型選「飛球」時，才會在紀錄上標「犧飛」。選「平飛」不會標，也沒有判斷是不是外野。
- 規則（9.08(d)）：未滿兩出局，外野手（或跑到外野的內野手）接殺飛球或平飛球，跑者因此得分，就是犧飛。犧飛不算打數，要記打點。
- 修正方向：
  - 符合條件時，在確認畫面直接標出「犧牲飛球（不算打數，打點 +1）」，讓記錄員送出前看到。
  - 條件：未滿兩出局、打擊類型為飛球或平飛、守位是外野、有跑者得分。
- 待查證：內野手跑到外野接殺算不算犧飛，工具要不要讓記錄員手動勾選。
- 測試：
  - 0 出局三壘有人，中飛，三壘跑者得分 → 犧飛，打數 0，打點 1。
  - 2 出局三壘有人，中飛接殺 → 第三出局，不得分，也不是犧飛。
  - 1 出局三壘有人，二壘手接殺內野飛球，跑者得分 → 不自動判犧飛（待查證）。

### B2. 犧牲觸擊的判定【預先列出】
- 未滿兩出局，觸擊出局，跑者推進 → 犧觸，不算打數。
- 待查證：記錄員判斷打者是在搶安打時，不算犧觸，要不要讓記錄員取消。

### B3. 打點的例外【預先列出】
- 雙殺打不記打點（9.04）。
- 失誤造成的得分，打點由記錄員判斷（待查證條件）。
- 四壞、觸身擠回得分要記打點。
- 修正方向：確認畫面顯示打點數字，允許記錄員手動修改。

## C. 跑者推進的合理性

### C1. 滾地出局時被擠的跑者不應預設「不動」【預先列出】
- 範例現況：出局類的跑者一律預設不動。
- 問題：一壘有人打滾地球，一壘跑者被迫離壘，實際上多半是進二壘或在二壘被封殺。
- 修正方向：滾地出局時，被擠的跑者預設「進一個壘」，沒被擠的跑者預設不動。

### C2. 全壘打的跑者不能選留壘【預先列出】
- 全壘打時所有跑者都要回本壘得分。例外只有跑者踩壘漏踏或超越前位跑者被判出局。

### C3. 跑者不能超越前面的跑者【預先列出】
- 範例只檢查「兩人同一壘」，沒檢查後面的跑者跑到前面跑者的前面。
- 修正方向：後位跑者的去向不能超過前位跑者，除非前位跑者出局。

### C4. 打者多跑一個壘也要選原因【預先列出】
- 範例中打者一安後改成上二壘，不會要求原因。
- 修正方向：打者去向和打擊結果不一致時，要選原因（趁傳球、失誤）。例外是打者在延伸推進時被刺殺，安打仍然成立。

### C5. 內野高飛必死球【預先列出】
- 打者自動出局，跑者不被擠，可以冒險推進。
- 修正方向：出局類型加入「內野高飛必死」，或當作飛球出局的一個標記（待討論）。

## D. 出局數與得分

### D1. 第三出局時得分是否有效【預先列出】
- 範例現況：第三出局是打者出局或封殺時，得分自動不算。觸殺只顯示提醒，不能選擇讓得分不算。
- 修正方向：觸殺第三出局時，讓記錄員選「跑者先踩本壘（得分有效）／觸殺在先（得分不算）」。

### D2. 一球超過三個出局【預先列出】
- 範例會把出局數卡在 3，但不會阻止記錄員點出第四個出局。
- 修正方向：超過三個出局時擋下，無法送出。

## E. 賽中調度

### E1. 板凳用完後無法調整守位【使用者測試】
- 問題：範例的守位畫面只能從「換人」或「換局」進入。板凳球員用完後，無法單純調換場上球員的守位，例如外野手和投手對調。
- 修正方向：「排守位」要能隨時直接進入，不依賴換人。守位互換本身就是一種調度，不需要板凳。
- 注意：一般賽制下外野手改投球只是守位互換；DH 制下牽涉 DH 取消，要走 Rule 5.11(a)(8)、(9) 的連動。
- 測試：
  - 一般賽制、板凳 0 人，右外野手與投手互換 → 可以完成，守位檢查通過，打序不變。

### E2. 範例未實作的 DH 取消路徑【預先列出】
- 投手改守其他守位（Rule 5.11(a)(8)）。
- 代打者之後上場投球（Rule 5.11(a)(9)）。
- 多重換人時由教練指定棒次（Rule 5.11(a)(5)）。
- 以上都要比照調度工具現有的 C2、C6、C7 測試。

## F. 其他待補

- 不死三振：聯盟是否採用（目前依標準規則：一壘空或兩出局才成立）。
- DH 規則：大漢聯盟是否採用 MLB Rule 5.11，還是業餘聯盟自己的版本。
- 防守半局、代跑、點開舊紀錄修改重算半局：範例都還沒做。
- 自責分、承繼跑者：防守半局才需要，要跟 C、D 類規則一起測試。
  - **承繼跑者（待辦，2026-10-07 決定先不做）**：依正式記錄規則 9.16(g)，換投時壘上的跑者之後得分，失分算前任投手；野手選擇時前任投手的跑者被封殺、打者上壘，打者改算前任投手。工具目前一律算給當時的投手
  - 自責分（ER）工具不判斷，由記錄員照說明書手填（`docs/自責分手填說明.md`）

## 測試案例格式（建議）

正式開發時，每條規則都寫成以下格式，當作 TDD 的測試：

| 欄位 | 說明 | 範例 |
|---|---|---|
| 開始狀態 | 出局數、壘上跑者 | 0 出局，三壘有人 |
| 操作 | 打者結果與例外調整 | 出局 › 飛球 › 中外，三壘跑者改成得分 |
| 預期結果 | 出局數、壘包、得分、打數、打點、標記 | 1 出局，壘上無人，+1 分，打數 0，打點 1，標「犧飛」 |
